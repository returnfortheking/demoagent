## Task 1: 真实 HiSpark 文档入库 (F30)

**commit:** `feat(F30): ingest real HiSpark documentation into Chroma knowledge base`

**新增文件:**
- `backend/scripts/ingest_docs.py` — 读取文档目录，分块，写入 Chroma 持久化存储
- `docs/hispark/` — 存放真实 HiSpark 官方文档（Markdown / PDF）

**修改文件:**
- `backend/src/chains/qa_chain.py` — `build_retriever` 指向持久化 Chroma 路径（保留 sample_docs 作为测试 fallback）

**接口规约:**
```
ingest_docs.py --input <dir> --persist <chroma_path> [--chunk-size N] [--chunk-overlap N]
输出: 入库文档数量、chunk 数量
```

**测试场景:**

| # | 场景 | 输入 | 期望 |
|---|------|------|------|
| 1 | 正常入库 | docs/hispark/ 目录含 ≥1 个 MD 文件 | 无报错，打印 chunk 数 |
| 2 | 路径不存在 | --input 指向空目录 | 报错提示，exit 1 |
| 3 | RAG 查询可命中真实内容 | "WS63 SDK 如何下载" | answer 包含 gitee 地址 |

**验收:**
```bash
cd backend && python scripts/ingest_docs.py --input ../docs/hispark/ --persist ./chroma_db
curl -s -X POST http://localhost:8000/chat \
  -H "Content-Type: application/json" \
  -d '{"message":"WS63 SDK如何下载","thread_id":"smoke"}' | python -m json.tool
```
预期: 入库成功；chat 返回包含真实文档内容的 answer

## Task 7: Webview UI 重设计 + 对话历史 + 来源展示 (F28)

**commit:** `feat(F28): redesign Webview chat UI with history and source citations`

**背景:** 当前 Webview 无视觉设计，无对话历史，无来源展示。本 Task 对齐成熟 Chat 产品（参考 Dify / Gradio Chat）的基础 UI 规范。

**范围:**

1. **视觉设计**
   - 气泡式对话布局：用户消息右对齐，AI 消息左对齐，区分配色
   - 固定顶部标题栏、固定底部输入区，中间滚动消息列表
   - 输入框支持多行，发送按钮在右侧
   - 流式输出期间显示打字指示器（loading dots 或 status-bar 文字）

2. **对话历史**
   - Session 内所有消息持久显示，不因新消息刷掉旧消息
   - 用户消息与 AI 消息交替排列，保留完整上下文可读性

3. **来源展示**
   - answer 类型消息下方展示 `sources` 折叠列表（默认收起，点击展开）
   - 每条 source 显示文档名或片段摘要

4. **BUG-01 修复（顺带）**
   - 修复 `stream-bubble` id 未清理导致的内容污染问题

**新增 / 修改文件:**
- Modify: `extension/src/webview/chatHtml.ts` — 重写 HTML 结构与内联 CSS
- Modify: `extension/src/webview/ChatPanel.ts` — sources 渲染逻辑、BUG-01 修复
- Modify: `extension/src/webview/streamingState.ts` — 如需调整状态机适配新 UI
- Create: `extension/src/test/suite/sourceDisplay.test.ts` — sources 渲染单测

**测试场景:**

| # | 场景 | 验证点 |
|---|------|--------|
| 1 | answer 消息带 sources | sources 列表渲染，条数与 API 返回一致 |
| 2 | sources 为空数组 | 不渲染来源区域 |
| 3 | 多轮对话 | 历史消息不被覆盖，滚动可查看 |
| 4 | BUG-01 | 连续两次流式请求，第二次内容不污染第一次气泡 |

**验收:**
```bash
npm test
npm run test:e2e  # E2E_MODE=gate
```
预期: 单测 PASSED；E2E Phase 2 流式消息正确渲染
