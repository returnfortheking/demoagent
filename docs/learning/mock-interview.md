## 第一类：深挖项目经历（以你的项目为素材，面试官最常问）

这类题考察你对自己项目的真实理解深度，答不上来就是简历注水。

**P1.** 你在 v0.2 里用 `RunnableWithMessageHistory` 实现了多轮对话，但 v0.2 的历史是存在内存 dict 里的。如果这个服务要水平扩展到 3 个实例，多轮对话会有什么问题？你打算怎么解决？

**P2.** 你的 RAG 链现在用 `k=3` 召回 3 个文档片段。如果用户问的问题需要跨多个文档的信息综合（比如"对比 Hi3861 和 Hi3516 的编译流程"），当前架构会有什么问题？你会怎么改？

**P3.** v0.2 的 `/chat/stream` 里，`classify_intent()` 是同步函数，在 async 上下文里直接调用。你说 v0.2 接受这个阻塞，v0.3 可以改成 `asyncio.to_thread`。能解释一下为什么同步函数会阻塞异步事件循环？`asyncio.to_thread` 是怎么解决这个问题的？

**P4.** 你的项目里 Prompt 是放在 `intent_v1.py` 里的独立文件。如果现在要做 A/B 测试——给 50% 的用户用 `intent_v1`，另外 50% 用 `intent_v2`——你的代码需要改哪里？怎么做到不重启服务？

**P5.** 你在 v0.1 里为什么没有直接用 `RetrievalQA.from_chain_type()`，而是在 v0.2 里改成手动组装 LCEL 链？除了"LCEL 更现代"，能说出具体的工程收益吗？

## 第二类：系统设计（AI Infra 必考，高薪岗位核心）

**S1.** 【经典题】设计一个支持 10 万用户的 LLM 问答服务。要求：P99 延迟 < 3s，支持流式输出，支持多轮对话。请描述你的架构，重点讲：
- 哪些部分会成为瓶颈？
- 会话状态怎么存？
- 如何做水平扩展？

**S2.** 你的项目用了 SSE 做流式输出。如果这个服务要支持 1 万并发长连接（每条 SSE 连接持续 10-30 秒），在基础设施层面会遇到什么挑战？Nginx 需要做什么特殊配置？

**S3.** RAG 系统的向量检索在高 QPS 下可能成为瓶颈。你知道哪些缓解手段？分别适用什么场景？（提示：从缓存、索引、异步预加载几个维度想）

**S4.** 你现在用 Chroma 做本地向量库。如果要把这个系统从"单机开发版"迁移到"生产版"，向量库选型你会怎么考虑？Chroma / Milvus / Qdrant / Pinecone 各适合什么规模和场景？

**S5.** LLM 调用是系统里最贵的部分。有哪些工程手段可以在不降低回答质量的前提下降低 LLM 调用成本？（至少说出 3 种，说出权衡）

## 第三类：RAG 进阶（结合项目深挖）

**R1.** 你的 RAG 现在是 chunk_size=500，overlap=50。如果用户的问题是"帮我总结这份文档的核心要点"，而文档有 5 万字，当前的切块策略会有什么问题？你会怎么改进？

**R2.** 召回的 3 个文档片段，你是直接全塞进 Prompt 的。如果这 3 个片段里有 1 个完全不相关（噪声），会对 LLM 的回答质量有什么影响？有什么工程手段可以在进 Prompt 之前过滤掉噪声片段？

**R3.** 用户问"上次你说的那个编译命令是什么"——这个问题本身没有任何技术关键词，向量检索会召回什么？结果有意义吗？这类"上下文依赖型"问题在 RAG 里怎么处理？

**R4.** 你的项目里 embedding 模型用的是智谱的 `embedding-3`。如果用户问题是英文，但知识库是中文文档，跨语言语义检索效果会怎样？有什么解法？

**R5.** RAGAS 的 Faithfulness 指标低，说明 LLM 在"幻觉"。但你怎么区分"LLM 用了 context 但理解错了"和"LLM 完全忽略 context 自己编的"这两种情况？从 Prompt 设计角度怎么缓解？

## 第四类：Agent 架构（v0.3 方向，面向未来）

**A1.** 你的 v0.2 是"意图分类 → action 或 RAG"的两路分支。如果要改成 LangGraph Agent，让 LLM 自主决定是执行命令还是查知识库，State 应该怎么设计？什么情况下 Agent 比固定分支更好，什么情况下反而更差？

**A2.** LangGraph 的 `interrupt_before` 可以做 Human-in-the-loop。你的项目里已经有了 `requires_confirmation` 字段，如果用 LangGraph Checkpointer 重新实现这个确认流程，对比现在的实现有什么优势和代价？

**A3.** 多 Agent 系统里，Supervisor 怎么避免"死循环"——子 Agent 互相等待或者 Supervisor 反复派同一个任务？LangGraph 有什么机制可以设置最大迭代次数？

**A4.** 你知道 Function Call 和 MCP 协议的区别。如果你的 HiSpark 工具集要开放给其他 AI 助手（比如 Claude Desktop、Cursor）直接调用，你会选择封装成 Function Call 还是 MCP Server？权衡是什么？

## 第六类：刁钻追问（面试官最爱用来区分候选人）

**T1.** LCEL 的 `|` 运算符背后是 `__or__` 方法的重载。那 `{"context": chain_a, "question": chain_b}` 这个 dict 是怎么变成 `RunnableParallel` 的？LangChain 在哪里做了这个转换？

**T2.** 你说 `StrOutputParser` 把 `AIMessage` 展开成字符串。如果 LLM 返回的是带 tool_call 的 `AIMessage`（比如 Function Call 的响应），`StrOutputParser` 还能用吗？应该用什么？

**T3.** `RunnableLambda` 包装的函数是同步的。如果这个函数需要做异步操作（比如查数据库），应该怎么写？LCEL 对异步 Lambda 有什么支持？

**T4.** 你的测试里用 `mocker.patch` 替换了 `_get_qa_chain`。如果两个测试并发运行（pytest-xdist），它们共享同一个模块命名空间，patch 会互相干扰吗？pytest-mock 是怎么保证测试隔离的？

**T5.** Node.js 的 `http.request` 是基于 EventEmitter 的回调模式。如果你要把 `sendMessageStream` 改成 `async/await` 风格（返回 `AsyncIterable<string>`），需要做什么？

## 面试策略提示

**答题框架（STAR + 技术深度）：**
```
现象/需求 → 我做了什么决策 → 为什么这样做（trade-off）→ 结果/收益 → 如果重来会怎么改
```

**高薪岗位拉开差距的关键：**
- 不只说"我用了 X"，要说"我选 X 不选 Y，因为在这个场景下..."
- 主动暴露 trade-off 和局限性，说明你理解边界
- 把项目经历和通用原理连起来（比如行缓冲 → 流式协议的普遍问题）

**当前 2026 年市场最热考点：**
1. 生产级 RAG（召回优化、评估、扩展性）
2. Agent 架构设计（LangGraph、工具编排、HITL）
3. LLM Infra（推理延迟优化、KV Cache、批处理）
4. 可观测性（LangSmith、指标设计、链路追踪）
