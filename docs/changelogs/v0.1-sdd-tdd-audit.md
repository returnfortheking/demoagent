# v0.1 SDD + TDD 审计结论（待优化项记录）

> 日期：2026-03-06  
> 目的：先固化问题结论，再进入改进方案讨论  
> 范围：方法论与执行质量（不评价技术栈新旧）

---

## 1) 审计范围与判定口径

- 仅评估 `v0.1` 在 SDD（规格驱动）与 TDD（测试驱动）上的落地质量。
- 明确排除项：`v0.1` 使用旧版本 LangChain 及相关栈是刻意策略，不作为问题上报。
- 重点看四件事：
  - 规格是否可执行、可追踪、可约束（不是只有文档描述）。
  - 测试是否真正执行了 Red-Green-Refactor，而不是“先有实现再补验证”。
  - 自动化门禁是否存在，能否把流程要求转化为强制约束。
  - AI 协作下是否有“看起来通过、实际未验证”的过程风险。

---

## 2) 结论总览（按优先级）

### P0（最高优先级）

1. **缺少自动化质量门禁，SDD/TDD 主要依赖人工执行。**
   - 未发现常见 CI 流水线配置（GitHub Actions/GitLab/Jenkins/Azure/Circle 等）。
   - 风险：计划要求、验收标准、纯度检查无法被持续强制执行。

### P1（高优先级）

2. **SDD 的单一事实源（SSOT）不稳定，存在“设计文档未来态”和“当前实现态”混写。**
   - 设计文档声明了 OpenAPI 与 ADR 等资产，但仓库当前未形成对应落地文件。
   - 风险：团队在“应遵循哪份规格”上会出现解释歧义。

3. **TDD 有明确原则，但执行证据显示曾发生“红灯阶段被跳过”。**
   - 复盘中明确记录预生成代码/测试导致 fail-first 不充分。
   - 风险：测试从“驱动设计”退化为“实现后验证”。

4. **前后端契约校验偏弱，存在“类型强转即通过”的隐藏风险。**
   - 客户端 `parseResponse` 直接类型断言，缺少运行时结构校验。
   - 风险：接口漂移时，测试可能不及时暴露契约破坏。

5. **测试分层边界被打破（unit 目录混入 integration 标记）。**
   - 风险：快速反馈层不再稳定，开发者难以获得低成本、可预测反馈。

6. **手动验收较多，但机判化 smoke 不完整。**
   - 复盘已显示“语法通过 != 运行时通过”的案例。
   - 风险：AI/子代理容易在“可运行性验证”上出现误判。

### P2（中优先级）

7. **需求-测试-结果追踪仍偏叙事化，机器可审计性不足。**
   - 已有计划与评估结果，但缺少统一的 trace matrix（Req -> Test -> Evidence）。
   - 风险：版本演进时难以快速确认“哪些需求被哪些证据覆盖”。

8. **非功能需求（可测试性、可观测性等）仍偏定性，缺乏可判定阈值。**
   - 风险：是否“达标”依赖主观解释，发布门槛不一致。

## 3) 关键证据（文件定位）

- `docs/plans/2026-03-02-v0.1-plan.md`
  - 有分层测试策略和任务验收命令，说明流程设计意识较完整。
- `docs/changelogs/v0.1-retrospective.md`
  - 明确记录 TDD 红灯阶段被跳过、以及语法检查替代运行时验证的问题。
- `docs/plans/2026-02-28-design.md`
  - 文档中声明 API 契约与 ADR 结构，但与当前仓库落地资产存在偏差。
- `extension/src/client/ApiClient.ts`
  - `parseResponse` 当前为直接类型断言，缺少运行时校验。
- `backend/tests/unit/test_qa_chain.py`
  - `unit` 目录中出现 `@pytest.mark.integration`，存在分层边界混入。
- `tests/e2e/test_e2e_v01.py`
  - 有全链路测试资产，但启动与诊断可观测性仍可增强。
- `scripts/check_src_purity.py`
  - 已有“生产代码纯度”检查脚本，是流程防线的良好起点。

## 4) 当前状态评价（不含改造方案）

- **优点**：有版本计划、有测试分层、有复盘与事故沉淀，方法论意识较成熟。
- **核心短板**：流程要求尚未被自动化门禁固化，导致执行一致性依赖个人自律。
- **结论一句话**：`v0.1` 已具备 SDD+TDD 的“框架”，但距离“可持续、可审计、可强制”的工程化闭环还有关键一步。

---

## 5) 下一步讨论清单（仅议题，不给方案）

1. 如何建立最小自动化门禁，先把“必须执行”变成“无法绕过”？
2. 如何定义 v0.2 的 SDD 单一事实源，避免文档未来态/当前态混写？
3. 如何在 AI 协作下强制保留 TDD 红灯证据链？
4. 如何提升跨栈契约测试强度，减少类型强转带来的隐性漂移？
5. 如何重整测试分层，使本地反馈回路稳定、快速、低成本？
6. 如何把复盘经验转化为可机判规则，而非仅经验文字？
