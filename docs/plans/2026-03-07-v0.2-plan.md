# v0.2 Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** 将所有链改写为 LCEL pipe 风格，支持流式输出（SSE），提取 Prompt 到版本化文件，锁定 API 契约。

**Architecture:**
- Backend: LLMChain/RetrievalQA → LCEL `prompt | llm | parser`，公共接口签名不变，调用方 `main.py` 无需修改
- Streaming: 新增 `POST /chat/stream`，FastAPI `StreamingResponse` + LCEL `.astream()`，`/chat` 保持非流式
- Prompts: 提取到 `src/prompts/` 目录，按版本命名，链文件不含内联字符串
- Extension: Node.js `http` 模块读取 SSE 流，通过 `postMessage` 推送 chunk 到 Webview，Webview 逐字显示

**Tech Stack:** `langchain_core.runnables`, `langchain_core.output_parsers` (JsonOutputParser, StrOutputParser), FastAPI StreamingResponse, Node.js `http` module

**Feature 覆盖:** F15–F22（见 feature-roadmap.md）

**测试分层策略:**
```
单元测试  → Mock chain，测逻辑正确性，每次 commit 必须全部通过
集成测试  → 真实 LLM + 真实 FastAPI，验证 LCEL 链有效性 + API 契约
E2E 测试  → Extension + Playwright，验证流式 UX 端到端正确性
```

## Task 2: 意图分类器 LCEL 重构 (F15)

**层次: 单元测试（Mock chain）**

### 接口定义

```
# backend/src/chains/intent_classifier.py

classify_intent(message: str) -> dict   ← 公共接口不变

内部变化:
  - 旧: _chain = LLMChain(...)，调用 _chain.run(message=message) 返回 str，手动 json.loads
  - 新: _chain = _prompt | get_llm() | JsonOutputParser()，调用 _chain.invoke({"message": message}) 直接返回 dict
  - _get_chain() 工厂函数保留（测试 mock 目标不变）

异常处理:
  - JsonOutputParser 抛出 OutputParserException → 捕获并转为 ValueError（保持公共接口）
  - chain 返回 type 字段不为 "action"/"answer" → 抛出 ValueError

行为变化（相较 v0.1）:
  - LLM 输出含前缀文字时（如 "好的！{...}"）：旧版抛 ValueError，新版 JsonOutputParser
    用正则提取 JSON，能正常解析，不再报错（行为更健壮）
```

## Task 4: SSE 流式端点 (F18)

**层次: 单元测试（httpx.AsyncClient + ASGITransport）**

### 接口定义

```
POST /chat/stream
Request:  { "message": string, "thread_id": string }   ← 与 /chat 相同
Response: text/event-stream

事件格式（answer 意图，每个 token 一条）:
  data: {"thread_id": "<tid>", "delta": "<token>"}\n\n

事件格式（action 意图，单条）:
  data: {"thread_id": "<tid>", "type": "action", "command": "...", "requires_confirmation": bool, "description": "..."}\n\n

终止标志（所有情况）:
  data: [DONE]\n\n

内部实现:
  1. 调用 classify_intent(message)（同步，与 /chat 相同）
  2. action 意图 → yield 一条 action 事件 → yield [DONE]
  3. answer 意图 → _get_qa_chain().astream(message) 逐 token yield → yield [DONE]
```

## Task 5: Webview 流式显示 (F19)

**层次: 单元测试（纯逻辑）+ E2E 测试（Playwright，含内容断言）**

### 接口定义

```typescript
// ChatPanel.ts — sendMessage 和 sendMessageStream 共存
sendMessage(message: string, threadId: string): void        ← v0.1 保留，调用 POST /chat（非流式）
sendMessageStream(message: string, threadId: string): void  ← v0.2 新增，调用 POST /chat/stream（流式）

// chat.html — 两个发送入口
发送按钮（非流式）→ 调用 sendMessage        ← 保留 v0.1 行为
流式发送按钮      → 调用 sendMessageStream  ← 新增

// sendMessageStream 流程:
  1. 立刻 postMessage({type: 'statusUpdate', text: '正在识别意图...'}) 给 Webview（~0ms）
  2. 用 Node.js http.request 发 POST /chat/stream，读取 SSE 响应体
  3. 收到 action 事件 → postMessage({type: 'statusUpdate', text: '执行中：<description>'})
                      → 调用 CommandExecutor.execute(actionEvent)（复用 F10/F11 逻辑，含危险确认）
                      → postMessage({type: 'actionDone', description: '<description>'})
  4. 收到 delta 事件 → postMessage({type: 'streamChunk', delta: '<token>'})
  5. 收到 [DONE]    → postMessage({type: 'streamDone'})

// chat.html Webview 侧 message 事件处理（新增 case）
statusUpdate → 显示 text 到独立状态栏元素 #status-bar
streamChunk  → 清空 #status-bar，在 #messages 中追加/创建流式气泡，append delta
streamDone   → 流式气泡 id 移除（定型）
actionDone   → 清空 #status-bar，在 #messages 中追加一条气泡："已执行：<description>"

// chat.html 新增 DOM 元素
<div id="status-bar"></div>  ← 独立状态栏，与消息气泡区分
```

**用户体验时序:**
```
用户点"流式发送" (~0ms)  → #status-bar 显示 "正在识别意图..."
classify_intent 返回 (~1~2s)
  [answer] 第一个 token → #status-bar 清空，流式气泡开始增长 → [DONE] 气泡定型
  [action] → #status-bar 变为 "执行中：编译项目"
           → CommandExecutor.execute()（flash 命令此处弹确认框）
           → #status-bar 清空，#messages 追加 "已执行：编译项目"
```

### 单元测试场景

**文件:** `extension/src/test/suite/streaming.test.ts`（新增）
